# Централизованное логирование на базе OpenSearch

В рамках задания был собран стек централизованного логирования для учебного CMS-приложения на основе OpenSearch. Исходный стенд был взят из предыдущего проекта на Elastic Stack и адаптирован под новые компоненты.

## Что было сделано

- Запущена базовая инфраструктура приложения: `nginx`, `php-fpm`, `postgresql`, которые формируют логи приложения, веб-сервера и базы данных.
- Компонент `filebeat` заменен на **Fluent Bit**, который читает логи из каталогов `./logs/nginx`, `./logs/php-fpm` и `./logs/postgresql` и отправляет их дальше по пайплайну.
- Компонент `logstash` заменен на **Data Prepper**, который принимает события от Fluent Bit по HTTP и передает их в OpenSearch.
- Вместо `Elasticsearch` развернут **OpenSearch**, а вместо `Kibana` — **OpenSearch Dashboards** для просмотра и визуализации логов.
- Подготовлен отдельный `docker-compose` для нового стека логирования, работающего в общей сети `cms-shared-net`, которая уже используется основным приложением.
- Исправлена проблема запуска OpenSearch: был задан валидный параметр `OPENSEARCH_INITIAL_ADMIN_PASSWORD`, потому что пароль по умолчанию не проходил встроенную проверку сложности.

## Состав нового стека

В итоговой конфигурации используются следующие сервисы:

- `fluent-bit` — сбор логов;
- `data-prepper` — обработка и маршрутизация событий;
- `opensearch` — хранение логов;
- `opensearch-dashboards` — просмотр логов и визуализация данных.

## Что должно быть запущено

Для корректной работы должны быть включены:

- `compose.core.yml` — базовое приложение с генерацией логов;
- `compose.opensearch.yml` — стек логирования на OpenSearch.

Старые compose-файлы от ELK/Beats должны быть остановлены, чтобы не было конфликтов по портам и дублирования функций.

## Результат

Логи приложения централизованно собираются Fluent Bit, проходят через Data Prepper, сохраняются в OpenSearch и доступны для просмотра через OpenSearch Dashboards.

ISM (Index State Management) — это аналог ILM (Index Lifecycle Management) в Elasticsearch, реализованный в OpenSearch. Политика автоматически управляет жизненным циклом индексов.

Созданная политика реализует три состояния:
| Состояние  | Возраст индекса | Действие                                    |
|------------|-----------------|---------------------------------------------|
| **hot**    | 0 — 7 дней      | Индекс активно используется, полные реплики |
| **warm**   | 7 — 30 дней     | Реплики уменьшаются до 0 (экономия места)   |
| **delete** | старше 30 дней  | Индекс автоматически удаляется              |

Автоматическое применение к новым индексам:
Благодаря блоку ism_template с паттерном logs-* политика автоматически применяется ко всем новым индексам, созданным Data Prepper (например, logs-2026.05.25, logs-2026.05.26 и т.д.) — без ручного вмешательства.
